# Stage3 v2 to v3 Semantic Delta

> Date: `2026-08-10`
>
> This is a migration record, not a second checklist.

## Why v3 is breaking

Stage3 v2 correctly introduced a sole checklist authority, lossless occurrence identity, complete-
relative-to-manifest semantics, a same-name Gantt and isolated Codex execution. The requested second
review round found that several apparently strong sentences were not yet backed by a closed evidence
or task ABI. V3 therefore changes acceptance semantics rather than merely adding examples.

## Stable IDs

Every v2 checklist ID is retained with its state. V3 appends new IDs only; it does not renumber or
reuse an existing ID. The newly reserved ranges cover:

- repository rights authority and an eighteen-agent audit input;
- independent clean-runner environment acceptance;
- catalog review/artifact denominator and post-curation population fixed point;
- physics proposal/entity/lineage routing and CS repair/evidence firewall;
- external benchmark roles, candidate ABI, semantic/scientific/CS scorers and sealed run replay; and
- M0387 kernel policy, declaration census, import topology, observed execution boundary, rights and
  cold-kernel checking.

## Corrected semantics

- The bounded review inventory is 98 legacy keys: 62 missing plus 36 collisions. V3 audit delta
  candidates are additional counted review inputs, never auto-allocated claims.
- CAT-010 becomes a pre-curation fixed point. A new post-curation fixed point owns final identity,
  allocation, terminal-descendant and domain-owner closure.
- A catalog ATV may be a claim, entity, event or aggregate. The theorem and open lists are query
  projections over truth-apt variants, not synonyms for the ATV population.
- miniF2F test informal proofs are public. An official split is not proof of Web/training secrecy.
- SciBench and TheoremQA scorer behaviors are comparator evidence, not scorer policy to copy.
- A warm M0387 pass remains evidence of local installation and integration only. Cold/cache/network,
  actual-read, resource and independent-runner claims require separate receipts.
- Checkbox state, a self-digest and a cleanup receipt cannot replace raw handoff, Master acceptance,
  fixed-matrix and accepted-tree currentness evidence.

## Execution optimization

V3 separates policy/schema work from data-dependent curation where the dependency is not real,
opens six conflict-free post-activation roots when prerequisites permit, permits controller modules
with disjoint ownership to be implemented in parallel, and introduces immutable physics/domain
partition artifacts before large curation files. Underfill remains truthful when genuine dependencies
or host/route limits bind.

## Compatibility

Stage2 remains historical. Stage1 remains a separate theorem-phase authority. Stage3 v2 projections
are replaced by v3 projections generated from the same authoritative path; no v2 checkbox is inferred
from an audit recommendation. Existing receipt and registry bytes remain immutable historical inputs.
