# THM-M-0148 frozen obligation architecture

## Freeze boundary

Registry version 1 freezes 37 canonical obligations for
`S56-M-0148-OBLIGATION_TREE` before any proof-closure status is credited. The
repository record says only "birational classification of higher-dimensional
algebraic varieties" and names the Mori minimal model programme. It does not
select one theorem, field, characteristic, base, dimension, variety or pair,
boundary, singularity class, positivity condition, termination scope, or
minimal-model/Mori-fibre conclusion.

The denominator therefore begins with `M0148-ROOT-IDENTITY`, the obligation to
select one immutable primary-source theorem branch. Every remaining signature
is explicitly `planned-identity-dependent`. None is an elaborated Lean target.
Selecting a cone, contraction, flip, termination, minimal-model existence, or
Mori fibre space theorem without source authority would substitute mathematics.

The authoritative theorem DAG has no direct hard parent, transitive hard
ancestor, hard edge, reuse hint, or shared group. Its required inspection order
is `[]`; that complete empty closure was traversed exactly once before this
freeze. No provider artifact, proof body, receipt, or acceptance state is used.

All mandatory `S/N/B/C/L/X/T` layers are present. Eligibility, exclusions, and
risk were assigned before recording the unchanged all-open
`H5 / M4 / R4` boundary. Selecting a theorem or changing any split, merge,
eligibility, or exclusion requires registry version 2 with an append-only
delta; version 1 remains reportable.

The proof and refinement graphs contain reciprocal
`proof_requires`/`composes` and

documentation, and workflow remain separate typed graphs and confer no proof
credit. Every graph indexes all 37 obligations. Every mathematical node is
reachable from the root in the union of forward proof and refinement edges;
the six `X` overlays are linked only through their own typed relations.

## Composition boundary

The conditional `ObligationTree.lean` role is not selected. There is no exact
root or child Lean type, so even an abstract harness would choose or invent the
theorem it purported to compose. The certificate list is therefore empty and
the bundle records
`not_machine_eligible_no_exact_parent_or_child_targets`. This is neither a
composition success nor a proof failure. Once the exact source claim exists,
every nonleaf must receive a checked harness consuming all exact children and
yielding its exact parent.
